## 파일과 실행

로컬 검토는 `full-ui/index.html`을 열거나 미리보기 서버의 `/full-ui/index.html?v=4.12.1`로 접속합니다. 폴더 구조를 유지해야 로컬 폰트와 이미지, 승인 화면이 표시됩니다. 인터넷 없이 열 수 있고 외부 폰트나 이미지 CDN을 사용하지 않습니다. 로컬 웹 서버를 쓸 경우 `docs/ui-handoff`를 제공하고 `/full-ui/index.html`로 접속합니다.

`screens.js`는 원본 32개 화면의 내용과 매핑, `experience.js`는 4.8의 추가 화면·캘린더·알림·일정 로컬 상태, `experience.css`는 해당 공통 컴포넌트, `hub.js` / `hub.css`는 4.10의 예약 관리 홈·캘린더 결과 묶음·기타 단체 입력·날짜 빠른 등록, `app.css`는 공통 컴포넌트, `app.js`는 로컬 상태와 화면 전환입니다. `approved-a2.html`은 승인된 A2의 예약 요청·예약 상세·받은 요청 화면을 재사용한 파일이며 `approved-bridge.js`가 나머지 화면과 더미 데이터를 연결합니다. 세 화면의 선택 모션과 날짜·시간 휠은 기존 공통 스타일과 스크립트를 사용합니다.

## 적용한 제품 규칙

- 단체 담당자는 파란색, 사장님은 초록색을 사용합니다. 일반 단체는 회식·뒤풀이·기타, 학생회 유형은 총회(개강·종강)·간식행사까지 선택합니다.
- 예약 요청은 한 페이지에서 영역이 펼쳐지는 승인 A2를 유지합니다. 연·월·일과 오전·오후·시·분은 같은 바텀시트 휠 규칙으로 선택하며 확인할 때만 반영합니다.
- 먼저 수락한 **한 가게**와 결제 대기 상태로 연결되고, 예약금 결제 후 확정됩니다. 기존 와이어프레임의 여러 수락 가게 중 선택하는 화면은 사용자 확인에 따라 요청 진행·수락 결과로 정리했습니다.
- 예약금은 사장님 입력 금액입니다. 0원이면 결제 없이 확정을 진행합니다. 과거 와이어프레임의 고정 10% 예약금이나 임의의 7일 환불 기준을 추가하지 않았습니다. 취소·환불 정책 문구는 팀 결정 대기 상태입니다.
- 거절·취소는 강조된 링크와 확인 시트로 구분하며, 정책 보기는 안내 위치로 유지합니다. 개인정보 없이 미충족 수요 조건을 보여줍니다.

## 검토할 수 있는 동작

역할 선택과 가입 입력, 단체·가게 정보 수정, 예약 요청과 수락·결제 시연, 수정 요청 응답, 메뉴 수량과 주문 합계, 참석 응답 수정과 인원 현황, 메뉴 추가·수정·판매 중지, 인식 결과 확인과 소비 기록 결과, 기간·상태 필터를 연결했습니다. 상단의 큰 글씨와 화면 상태 선택은 제품 화면 밖에 있는 검토 도구입니다. 요청 진행 화면에는 응답 대기·수락 결과·만료 검토 버튼이 있습니다.

로그인·소셜 로그인·결제·요청 전송·사진 인식은 실제 서버와 연결되지 않은 UI 시연입니다. 선택한 사진은 업로드하지 않으며 인식 결과는 수정 가능한 예시 데이터입니다. 참석 링크도 이 시안의 해당 화면을 여는 링크이며 다른 기기의 응답을 수집하지 않습니다. 새로고침하면 더미 상태가 초기화됩니다. 대시보드의 집계는 예시 데이터로, 편집한 영수증의 실제 매출 집계가 아닙니다. 수정 요청 기한·횟수 등 서버 권한 검사는 추후 실제 서비스에서 구현해야 합니다.

초기 예시 일정은 2026년 10월이며, 새 예약 날짜는 한국 시간 기준 오늘부터 선택할 수 있습니다. 변경 시 요일과 월별 일수·윤년을 계산합니다. 화면 확장 과정에서 통일한 원본 차이는 `source-map.md`에 기록했습니다. 매니패스트 공유 페이지는 보기 전용이어서 원본 사이트를 수정하지 않았습니다.

## 4.12 백엔드 좌석 배치도 명세 반영

2026-10-07 확인한 `2026-KW-HACKATHON/14_Kangcompany`의 `feat/seat-layout` 브랜치, 커밋 `f757627bccbee3b8923537f440107ea50781d6d5`를 기준으로 현재 시연 페이지를 완성했습니다. 확인 당시 좌석 기능의 별도 PR은 없었으며 브랜치의 API 문서·009 마이그레이션·인식 함수·React 조회/관리 화면을 읽었습니다. [검토 근거](reference/seat-layout/README.md). 실제 React 앱이나 DB에는 변경하지 않았습니다.

- 37번은 게시된 배치도가 있는 가게만 검색·선택합니다. 테이블을 누르면 이름·좌석 수·형태가 표시되며 배치 수정이나 좌석 지정은 제공하지 않습니다. 없는 가게의 직접 진입은 해당 가게의 미게시 상태로 표시합니다.
- 38번은 현재 공개한 배치도와 테이블 수·좌석 합계·가게 최대 인원을 보여줍니다. 사진으로 시작하거나 직접 그리기를 선택합니다. 편집 중에도 이전 게시본이 유지됩니다.
- 39번은 테이블 이름·1–30석·사각/원형·위치·크기와 입구/카운터/주방/화장실/창가/기타 시설을 편집하고 바로 게시합니다. 임시 저장과 일반 손님의 수정 제안은 없습니다. 겹침·좌석 부족·낮은 인식 신뢰도는 경고이며 겹침은 확인 후 게시할 수 있습니다. 빈 배치·중복 이름·유효하지 않은 입력은 게시를 막습니다.
- 17번 캘린더의 ‘좌석 배치도’와 11번 예약 상세에서 37번으로 진입합니다. 사장님 21번 운영 메뉴에서 38번으로 진입합니다. 기존 하단 캘린더는 유지합니다. 브랜치의 가게 탐색/예약 상세 및 사장님 운영 화면 진입 흐름을 현재 시안에 대응했습니다.

데이터는 `width:100`, `height:40..200`, `tables[]`, `fixtures[]`이며 좌표는 왼쪽 위 기준입니다. 게시 데이터는 `p_store_id`, `p_layout`, `p_source` 구조와 일치하고 인식 신뢰도는 저장 전 제거합니다. BE의 정규화·경계 보정·겹침·요약 함수를 [원본 스냅샷](reference/seat-layout/layout.ts)과 [시연용 순수 함수](seating-contract.js)로 유지합니다. 임의의 회전값·메모·이미지 파일을 게시 데이터에 추가하지 않았습니다.

사진 인식 API의 요청/응답 구조까지 반영했지만 **이번 범위는 서버에 연결하지 않는 현재 시연 페이지**입니다. 선택 사진은 로컬 미리보기만 제공하며, 성공·오류·빈 결과를 예시로 확인할 수 있습니다. 실제 인식 결과나 실제 게시 성공으로 표현하지 않습니다. 모든 변경은 현재 탭의 메모리에만 저장되고 새로고침하면 초기화됩니다.

[배치도 확인 84개](screenshots/seating-412-verification.json)와 [기존 기능 확인 59개](screenshots/regression-verification-412.json)를 통과했습니다. 작은 화면·큰 글씨·검색·미게시 가게·키보드 편집·좌석 제한·시설·게시 데이터·겹침 확인·인식 예시의 세 가지 결과를 포함합니다.

## 4.12.1 여유 있는 둥근 항목 버튼

메뉴 행·홈 바로가기·알림·예약 준비 영역·예약 요청 펼치기 제목·다음 단계 버튼에 반경 20px, 사방 여백 16px, 최소 높이 80px를 적용했습니다. 항목 사이 간격은 8px이며 구분 테두리를 제거했습니다. 누르는 동안에도 같은 둥근 모서리를 유지하고 기존 파랑/초록의 옅은 색으로 즉시 반응합니다. 필터의 긴 선택 영역과 날짜 선택은 각각 기존 규칙을 유지합니다. [디자인 토큰](../design/design-tokens.md)의 항목 버튼 규칙으로 관리합니다.
