# 04. 소셜 로그인 설정 (카카오·네이버)

로그인 화면(A-02)의 카카오·네이버 버튼은 **Supabase 에서 해당 제공자를 켜야** 눌린다. 켜지 않으면 버튼이 회색으로 "준비 중"이라고 나온다 (앱이 `GET /auth/v1/settings` 로 확인).
작성 2026-10-08. 카카오·네이버·Supabase 화면 문구는 바뀔 수 있으니 비슷한 메뉴를 찾을 것.

## 0. 먼저 할 것

1. Supabase SQL Editor 에서 `wolgyedeoring-backend/supabase/migrations/010_social_login.sql` 실행
   - 소셜로 처음 들어온 사람의 이름을 카카오·네이버 이름으로 저장하고, 단체·가게 등록 전까지 역할을 고를 수 있게 한다 (`choose_role`)
2. Supabase → Authentication → **URL Configuration**
   - Site URL: 배포 주소 (예 `https://wolgyedeoring.vercel.app`)
   - Redirect URLs: `https://<배포 주소>/**`, 로컬 확인용 `http://localhost:5173/**`
   - 로그인 후 앱의 `/login` 으로 돌아온다. 여기 없는 주소면 Site URL 로 돌아간다
   - 비밀번호 찾기 메일 링크(`/reset-password`)도 이 설정을 쓴다
3. Supabase 콜백 주소 확인: Authentication → Providers → Kakao 를 펼치면 보이는 **Callback URL**
   `https://<프로젝트ID>.supabase.co/auth/v1/callback` — 카카오·네이버 양쪽에 이 주소를 등록한다

## 1. 카카오 (Supabase 기본 제공)

공식 안내: https://supabase.com/docs/guides/auth/social-login/auth-kakao

1. https://developers.kakao.com → 내 애플리케이션 → 앱 만들기 (지도용 앱이 있으면 같은 앱 사용 가능)
2. **REST API 키** 복사 → Supabase 의 Client ID
3. 카카오 로그인 **활성화** → Redirect URI 에 위 Supabase 콜백 주소 등록
4. 보안 → **Client Secret** 코드 생성·활성화 → Supabase 의 Client Secret
5. 동의항목: 닉네임(필수), 프로필 사진(선택). **이메일은 비즈 앱 인증이 있어야 받을 수 있다**
6. Supabase → Authentication → Providers → **Kakao** 켜기, Client ID·Secret 입력
   - 이메일 동의항목이 없으면 **"Allow users without an email"** (이메일 없는 사용자 허용) 을 켠다. 안 켜면 로그인 후 오류가 난다

## 2. 네이버 (Supabase 사용자 정의 제공자)

네이버는 Supabase 기본 제공자가 아니라 **Custom OAuth/OIDC Providers** 로 붙인다.
공식 안내: https://supabase.com/docs/guides/auth/custom-oauth-providers

1. https://developers.naver.com → Application → 애플리케이션 등록
   - 사용 API: **네이버 로그인**, 제공 정보: 이름(또는 별명)
   - 서비스 URL: 배포 주소 / Callback URL: 위 Supabase 콜백 주소
   - Client ID·Client Secret 복사
2. Supabase → Authentication → Providers → **Custom providers 추가** → 종류 **OAuth2**
   - 식별자: **`naver`** (앱은 `custom:naver` 로 호출한다. 다른 이름으로 만들면 `src/api/auth.ts` 의 `PROVIDER_ID` 도 바꿀 것)
   - Authorization URL: `https://nid.naver.com/oauth2.0/authorize`
   - Token URL: `https://nid.naver.com/oauth2.0/token`
   - User info URL: `https://openapi.naver.com/v1/nid/me`
   - Client ID·Secret: 네이버에서 받은 값
3. ⚠️ 네이버 사용자 정보는 `{ resultcode, message, response: { id, name, nickname, … } }` 처럼 **`response` 안에** 들어 있다. Supabase 의 사용자 정보 매핑 설정에서 id·이름을 `response.id`, `response.name` 으로 지정할 수 있는지 확인하고, 처음 한 번은 직접 로그인해서 Authentication → Users 에 계정이 제대로 생기는지 볼 것
4. 무료 플랜은 사용자 정의 제공자 수 제한이 있을 수 있다 (안내 기준 3개)

## 2-1. 네이버 개발 중 상태

네이버 앱이 "개발 중"이면 **등록한 테스트 아이디만** 로그인된다. 발표에서 다른 사람이 쓰게 하려면 검수 요청이 필요하므로, 시연은 팀원 아이디를 테스트 아이디로 등록해 두는 것을 권장.

## 3. 앱에서 일어나는 일

1. 시작 화면에서 역할(단체 담당자 / 가게 사장님)을 고르고 "로그인" → 카카오·네이버 버튼
2. 처음이면 Supabase 가 계정을 만들고(역할 기본 '단체'), 앱이 시작 화면에서 고른 역할로 바꾼다 (`choose_role`)
3. 단체·가게 등록 화면으로 이동. 이름·연락처를 확인하고 등록
4. 역할을 잘못 골랐으면 등록 화면 아래 "사장님으로 시작하기 / 단체 담당자로 시작하기" (등록 전까지만)

## 4. 확인

- 로그인 화면에서 버튼이 노란색·초록색으로 눌리는지 (회색 "준비 중"이면 Supabase 에서 제공자가 꺼져 있음)
- 로그인 후 `/login?error_description=…` 로 돌아오면 화면 위에 오류가 보인다. 자주 나는 것:
  - `redirect_uri mismatch` → 카카오·네이버에 등록한 콜백 주소가 Supabase 콜백과 다름
  - `Error getting user email` → 카카오 "이메일 없는 사용자 허용"이 꺼져 있음
