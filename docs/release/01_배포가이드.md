# 01. 프런트 배포 가이드 (Vercel)

목표: 누구나 휴대폰으로 열 수 있는 주소(`https://….vercel.app`)를 만든다. 제출·발표·전시회 주민 투표용.
작성 2026-10-06. Vercel 화면 문구는 바뀔 수 있으니 비슷한 메뉴를 찾을 것.

## 0. 먼저 정할 것

- **배포 담당 1명**: 그 사람의 GitHub 계정으로 Vercel에 로그인한다.
- **배포할 브랜치**: `main` (FE PR 머지 후). 머지 전에 미리 보려면 `feat/fe-api-layer`나 이 브랜치를 골라도 된다.
- 조직 저장소(`2026-KW-HACKATHON`)라서, Vercel이 저장소 목록에 안 보이면 **조직 관리자가 Vercel GitHub App 설치를 허용**해야 한다 (아래 5절).

## 1. 프로젝트 만들기

1. https://vercel.com → **Continue with GitHub**
2. **Add New… → Project** → `14_Kangcompany` 옆 **Import**
3. 설정 화면에서:

| 항목 | 값 |
|---|---|
| Framework Preset | **Vite** (자동 인식 안 되면 직접 선택) |
| Root Directory | **`wolgyedeoring-frontend`** (Edit 눌러 폴더 선택) |
| Build Command | `npm run build` (기본값) |
| Output Directory | `dist` (기본값) |

4. **Environment Variables** 펼쳐서 추가:

| Name | Value |
|---|---|
| `VITE_SUPABASE_URL` | `https://<프로젝트ID>.supabase.co` (**https:// 한 번만**, 끝에 `/` 없음) |
| `VITE_SUPABASE_ANON_KEY` | publishable 키 `sb_publishable_…` (또는 anon `eyJ…`). **Secret 키 금지** |
| `VITE_TOSS_CLIENT_KEY` | (선택) 토스 테스트 **클라이언트** 키 `test_ck_…`. 없으면 "시연용 결제" 버튼으로 대체 |
| `VITE_KAKAO_MAP_KEY` | (선택) 카카오 JavaScript 키. 없으면 지도 자리 표시 |

5. **Deploy** → 1~2분 뒤 주소가 나온다.

> 환경변수를 나중에 바꾸면 **Deployments → 최신 배포 ⋯ → Redeploy** 해야 반영된다 (빌드할 때 값이 박힌다).

## 2. 배포 후 바로 확인 (5분)

1. `https://<주소>/dev` → 시연 계정 버튼 → ✅ 표
2. `https://<주소>/owner/inbox` 를 주소창에 직접 쳐서 **새로고침** → 404 가 아니라 시작/로그인 화면이 나와야 정상 (`vercel.json` 이 처리)
3. 휴대폰으로 같은 주소 → 로그인 → 하단 탭

## 3. 다른 서비스에 등록할 주소

| 어디 | 무엇을 | 왜 |
|---|---|---|
| Supabase → Authentication → **URL Configuration** | Site URL 을 배포 주소로, Redirect URLs 에 `https://<주소>/**` 추가 | 회원가입 확인 메일 링크가 배포 주소로 돌아오게 (데모 계정만 쓰면 필수 아님) |
| 카카오디벨로퍼스 → 앱 → 플랫폼 키 → JavaScript 키 → **JavaScript SDK 도메인** | `https://<주소>` | 지도 키를 쓸 때만. 안 하면 지도에 401 domain mismatched |
| 토스 | 등록 불필요 | 결제 복귀 주소는 앱이 현재 주소로 자동 지정 |

## 4. 자주 나는 문제

| 증상 | 원인·해결 |
|---|---|
| 빌드 실패: `tokens.css` 를 찾을 수 없음 | 프런트가 저장소 상위 폴더의 `docs/ui-handoff/design/tokens.css` 를 직접 불러온다. Project → Settings → Build and Deployment → Root Directory 아래 **"Include files outside the root directory in the Build Step"** 이 켜져 있는지 확인 |
| 화면에 "연결을 확인해 주세요" | `VITE_SUPABASE_URL` 오타 (https 중복 등) → 고친 뒤 Redeploy |
| 화면 첫 줄에 ".env.local 이 없습니다" | 환경변수 이름 오타 (`VITE_` 접두어 필수) → Redeploy |
| 하위 주소 새로고침 시 404 | Root Directory 가 `wolgyedeoring-frontend` 가 아니어서 `vercel.json` 을 못 읽음 |
| 저장소가 목록에 없음 | 5절 |

## 5. 조직 저장소 권한 (저장소가 안 보일 때)

Vercel 화면의 **Adjust GitHub App Permissions** (또는 https://github.com/apps/vercel ) → `2026-KW-HACKATHON` 선택 → `14_Kangcompany` 허용.
조직 Owner 권한이 필요할 수 있다. 안 되면:
- **대안 A**: 담당자 개인 계정으로 저장소를 **Fork** → 그 Fork 를 Vercel 에 연결 (main 머지 후 Fork 에서 Sync fork 눌러 갱신)
- **대안 B (Netlify)**: https://app.netlify.com → Add new site → Import from Git → Base directory `wolgyedeoring-frontend`, Build `npm run build`, Publish `wolgyedeoring-frontend/dist`, 환경변수 동일. 새로고침 404 는 `public/_redirects` 가 처리한다

## 6. 배포 이후

- `main` 에 PR 이 머지될 때마다 자동으로 다시 배포된다.
- PR 을 올리면 Vercel 이 PR 마다 **미리보기 주소**를 댓글로 달아 준다 → 디자인 리뷰에 그대로 쓰면 된다.
- 시연 직전: SQL Editor 에서 `wolgyedeoring-backend/scripts/seed_demo.sql` 다시 실행 (데이터 초기화).
