# 03. 시연 대본 (리허설 체크리스트)

기준: `docs/ui-handoff/personas.md` 6장 "학생회 × 사장님 시연", 데모 데이터 `seed_demo.sql`, 화면 골격(`feat/fe-api-layer`).
발표에서는 **가상 인물·시연 데이터임을 밝히고**, 효과(조율 시간 단축·노쇼 감소)가 관찰됐다는 표현은 쓰지 않는다 (페르소나 문서 원칙).

## 0. 시연 전 준비 (30분 전)

- [ ] SQL Editor 에서 `wolgyedeoring-backend/scripts/seed_demo.sql` 실행 (데이터 초기화, 날짜는 실행 시점 기준)
- [ ] **브라우저 2개**: 단체용(예: Chrome) / 사장님용(예: Edge 또는 시크릿 창). 같은 브라우저 일반 창 2개는 로그인이 공유되므로 안 됨
- [ ] 화면 공유: 두 창을 좌우로 배치, 확대 125% 정도. 휴대폰 화면처럼 보이려면 F12 → 기기 모드(Ctrl+Shift+M)
- [ ] 참석 응답용 휴대폰 1~2대 (배포 주소일 때만. 로컬이면 PC 시크릿 창으로 대체)
- [ ] 실물 영수증 1장 (선택, 6단계)
- [ ] 미리 로그인: 단체 창 `sw@wolgye.demo`, 사장님 창 `owner1@wolgye.demo` (비밀번호 모두 `demo1234!`)

| 페르소나 | 계정 | 화면 |
|---|---|---|
| 김서연 (소프트웨어학부 학생회장) | `sw@wolgye.demo` | 단체 |
| 박정호 (고기굽는집 사장님) | `owner1@wolgye.demo` | 사장님 |
| (보조) 월계치킨 사장님 | `owner2@wolgye.demo` | 선착순 마감 보여줄 때 |

## 1. 문제 제시 (말로, 30초)

> "학생회는 매 학기 개강총회·간식행사·종강총회 때마다 가게에 일일이 전화해 날짜를 맞추고, 가게는 큰 예약이 노쇼 날까 부담입니다. 월계더링은 **날짜·인원·예산만 올리면 가게가 먼저 수락**하고, **예약금으로 확정**합니다."

## 2. 요청 (서연, 단체 창, 1분)

1. 홈 → **예약 요청하기**
2. 행사 종류 `개강총회`, 날짜 **7일 뒤 18:30**, 인원 `24`, 1인 예산 `25000`
3. 화면 하단 "**3곳에 요청이 전달돼요**" 와 예상 총액 600,000원을 짚는다
4. **요청 보내기** → 요청 상태 화면: `응답 대기` + 응답 기한 카운트다운

> "전화 대신 한 번에 조건 맞는 가게 전부에 갑니다. 가장 먼저 수락한 가게로 바로 정해져요."

## 3. 수락 (정호, 사장님 창, 1분)

1. 사장님 창 새로고침 → 홈 "새 요청" 에 소프트웨어학부 학생회 카드 (상단 🔔 점, 토스트 알림)
2. 카드 → 요청 상세: 응답 기한, **같은 시간대 남은 자리**, 예상 총액
3. 예약금 `50000` 확인 → **수락하기** → 확인 창 → 예약 상세(`결제 대기`)

> "사장님은 '이 시간에 자리가 있나'를 앱이 계산해 줍니다. 수락하면 바로 이 가게로 정해지고, 결제 전까지는 '결제 대기'입니다."

**(선택, 선착순 보여주기)** 미리 `owner2@wolgye.demo` 로 같은 요청을 열어 둔 창에서 수락 → "이미 마감되었거나 없는 요청입니다" + 알림 "다른 가게가 먼저 수락해 요청이 마감되었습니다"

## 4. 확정 (서연, 단체 창, 1분 30초)

1. 단체 창: 토스트 "고기굽는집이(가) 수락했어요" (안 뜨면 🔔 알림 목록) → 누르면 예약 상세
2. **사전 주문 → 메뉴 고르기**: 삼겹살 24, 된장찌개 6, 소주 10 → 1인당 금액·예산 비교 → 저장
3. **예약금 50,000원 결제하기**
   - 토스 키가 있으면: 토스 테스트 결제창 → 결제 → "예약이 확정됐어요"
   - 없으면: **시연용 결제** 버튼 (발표 때 "테스트 결제"라고 말할 것)
4. 상태 `확정`, 사장님 창 새로고침 → 같은 예약이 `확정`, 사전 주문(준비량)이 그대로 보임

> "양쪽에 같은 예약, 같은 주문이 보입니다. 사장님은 미리 준비량을 압니다."

## 5. 참석 조사 (서연 → 참석자, 1분)

1. 예약 상세 → 참석 조사 **만들기** → 안내 문구 입력 → 만들기 → **링크 공유하기**(복사)
2. 휴대폰(또는 시크릿 창)에서 링크 → 로그인 없이 이름·참석 → 응답 보내기
3. 단체 창 **참석 현황** 에 실시간으로 응답이 늘어나는 것 확인

⚠️ **시연에서는 "참석 조사 마감하기"를 누르지 말 것.** 마감하면 예약 인원이 참석 응답 수(예: 2명)로 바뀐다.
마감 결과를 보여주고 싶으면 시드의 **축구 동아리 KW FC × 월계치킨** 예약(응답 18명 중 참석 15명 → 예약 인원 15명 반영)을 `fc@wolgye.demo` 로 보여준다.

## 6. 행사 후 기록 (정호 → 서연, 1분 30초)

행사 시작 전에는 완료 처리가 막혀 있으므로(규칙), **이미 끝난 시드 예약**으로 보여준다.

1. 사장님 창 홈 → "**확인이 필요한 영수증**" 카드 (고기굽는집의 가장 최근 완료 행사)
2. 보정 화면: 빨간 테두리 2줄
   - `맥 주` 줄: 수량·단가와 금액이 안 맞음 → 수량 1, 단가 5000 확인 후 저장 (또는 금액에 맞게 수정)
   - `공기밥추가?` 줄: 메뉴 미매칭 → 메뉴 선택에서 `공기밥` → 저장
3. **영수증 확정하기** 켜짐 → 확정 → 상태 `확정`
4. 카드에 적힌 **단체 이름**으로 단체 계정 로그인 (아래 표) → 예약 → 지난 예약 → 해당 예약 → "**실제 소비 기록**" (총액, 1인당, 품목)

| 단체 이름 | 계정 |
|---|---|
| 소프트웨어학부 학생회 | sw@wolgye.demo |
| 전자공학과 학생회 | ee@wolgye.demo |
| 밴드 동아리 소리모아 | band@wolgye.demo |
| 축구 동아리 KW FC | fc@wolgye.demo |
| 월계1동 주민모임 | town@wolgye.demo |

**(선택) 실물 영수증**: 사장님 창 → 요청·예약 → 예약 → 지난 예약 중 `완료` 하나 → 영수증 등록 → 촬영. 메뉴 이름이 달라 "확인 필요"로 나오는 것이 정상 → 위와 같은 보정 흐름. **Edge Function 점검(02 문서)을 마친 경우에만**.

> "사진은 저장하지 않고 금액·품목만 남깁니다. 사장님이 확인한 기록만 분석과 단체 기록에 반영됩니다. 회계 증빙은 영수증 원본이 따로 필요합니다."

## 7. 분석 (정호, 30초)

사장님 창 → **분석** 탭: 요일별 예약(한산한 요일), 많이 나간 메뉴, 단체별 → **놓친 단체 수요 보기**

> "조건 맞는 가게가 없어 끝난 요청도 쌓입니다. 사장님은 한산한 날 빈 날짜를 먼저 열어 그 수요를 잡을 수 있습니다." (가게 찾기 탭/빈 날짜 관리로 연결해도 됨)

## 실패 시 대처

| 상황 | 대처 |
|---|---|
| 알림 토스트가 안 뜸 | 🔔 알림 목록 또는 새로고침 (Realtime 지연) |
| 수락 버튼 비활성 "자리 부족" | 같은 시간대에 다른 예약이 있음 → 날짜를 하루 옮겨 다시 요청 |
| 요청이 사장님 목록에 없음 | 인원이 가게 최대 인원 초과, 또는 응답 기한 지남 → 조건 바꿔 다시 요청 |
| 토스 결제창 오류 | 결제창 닫고 "시연용 결제"로 (토스 키를 비운 배포/로컬로 전환) |
| 꼬였을 때 전체 초기화 | `seed_demo.sql` 다시 실행 (1분) → 브라우저 새로고침 |
